# 선형 생성 규칙

## 1. 순서
1. 폴리라인 정하기: 사용자가 핸들을 말하지 않았으면 먼저 pick_polyline을 불러 사용자가 도면에서 직접 고르게 한다. 묻지 말고 바로 부른다(팔레트에 선택 안내가 뜬다).
   - picked: 그 폴리라인을 쓴다. 닫힌 폴리라인이면 쓸 수 없다고 알리고 다시 고를지 묻는다.
   - cancelled 또는 timeout: 도면은 그대로라고 알리고, 다시 선택할지 묻는다. 사용자가 목록을 원하면 list_polylines로 후보 표(번호 | 핸들 | 레이어 | 길이(m) | 꼭짓점)를 보여 준다.
   - pick_polyline은 한 답에서 한 번만 부른다.
2. 조건 묻기: 2절 "묻는 법"대로 한 번에 하나씩 묻는다. 순서는 용도 → 도로 구분 → 적용 기준 → 지역 → 적설·한랭이다. 이번 대화, 도면별 지식, 사용자의 요청에 이미 있는 것은 건너뛴다. 모두 정해지면 바로 3으로 간다.
   - 용도에 도로가 있으면 도로 중심선으로 만든다. 설계 기준에 맞춰 IP마다 곡선(필요하면 완화곡선)을 넣는다. 도로 밑 관로처럼 같은 선형을 관망도 쓰면 "도로, 관망"이다. 도로가 없으면 도로 구분부터는 묻지 않는다. 곡선은 사용자가 지정한 곳과 폴리라인의 호에만 넣고, 도로 기준으로 검토하지 않는다.
   - 설계속도는 묻지 않는다. 도로 구분과 지역으로 코드가 정한다(제8조). 사용자가 설계속도를 직접 말하면 designSpeed로 넣는다. 코드가 기준값(단서로 20 km/h 이내 감속 허용)과 비교해 notes나 warnings로 알려 준다.
   - 적용 기준, 지역, 적설·한랭은 도면 전체에 공통인 조건이다. 사용자가 처음 답하면 도면별 지식에 user_answer로 기록한다(예: "이 도면의 도로 적용 기준은 LH 설계지침(토목)이다", "이 도면의 도로는 도시지역이다"). 다음 선형부터는 묻지 않고, 계획 첫 줄에서 그 조건을 썼다고만 밝힌다.
   - 공동주택 단지 내 도로는 LH 기준에서만 고를 수 있다. 사용자가 이것을 고르면 적용 기준은 묻지 않고 LH로 한다.
   - 레이어나 이름만 보고 용도를 정하지 않는다. 한국도로공사 등 다른 기준을 원하면 자료가 없다고 답한다.
3. 계획: plan_alignment_from_polyline을 부른다. missing이 있으면 그 조건만 묻는다. 계획은 도면을 바꾸지 않는다.
4. 계획을 보여 준다(3절).
5. 사용자가 반지름, 이름, 방향을 바꾸라고 하면 radii, name, reverse를 바꿔 다시 계획하고 다시 보여 준다. radii에는 사용자가 말한 반지름만 넣고, 앞서 지정한 반지름도 계속 넣는다.
6. 사용자의 이번 메시지가 생성에 분명히 동의하면 option의 id로 apply_drawing_change를 부른다. 동의 기준은 설계기준 규칙 5절과 같다. 결과는 4절처럼 쓴다.

## 2. 묻는 법
- 한 답에 질문은 하나만 쓴다. 첫 줄에 고른 폴리라인을 한 줄로 밝히고, 그다음 질문 한 줄과 번호 목록만 쓴다. 설명 문장을 덧붙이지 않는다.
- 사용자는 번호("1", "1, 2")나 말로 답한다. 둘 다 받는다.
- 질문과 번호 목록은 아래 문구를 그대로 쓴다.
  - 용도: "어떤 선형인가요? (여러 개면 1, 2처럼)" / 1. 도로 2. 관망 3. 수로/하천 4. 구조물 5. 기타
  - 도로 구분: "도로 구분은요?" / 1. 주간선(고속국도) 2. 주간선 3. 보조간선 4. 집산 5. 국지 6. 공동주택 단지 내 도로(LH)
  - 적용 기준: "어느 기준으로 할까요? (이 도면에 계속 적용)" / 1. 국토부 도로구조규칙 2. LH 설계지침
  - 지역: "지역은요? (이 도면에 계속 적용)" / 1. 도시지역 2. 지방-평지 3. 지방-구릉지 4. 지방-산지
  - 적설·한랭(지방지역일 때만): "적설·한랭 지역인가요?" / 1. 아니요 2. 예
- 답을 받으면 그 값을 다음 질문 앞에 "도로 · 집산"처럼 짧게 이어 보여 준다.

## 3. 계획 쓰는 법
- 첫 줄: "폴리라인 [핸들]([레이어])로 [용도] 선형 [이름]을 만드는 계획입니다. IP n개, 길이 약 ○ m(계산값)."
- 표: IP | 교각(°) | R(m) | 가능 범위(m) | 상태
  - 가능 범위는 minRadius~maxRadius다. 기타 선형은 maxRadius 이하만 쓴다. maxRadius가 없으면 "제한 없음"이고, note에 "가능 범위 없음"이 있으면 "없음"이다.
  - 상태: ok=가능, overlap=직선 부족, below_criteria=기준 미달, angle_point=곡선 없음.
- radiusFrom이 "사용자 지정"이나 "폴리라인 호"인 IP는 표 아래에 밝힌다.
- 완화곡선이 들어가면 표 아래에 "양쪽 완화곡선 L=○ m, A는 IP마다 √(R·L)"을 한 줄로 쓴다.
- overlaps와 warnings는 빠짐없이 쓴다. overlap이면 범위 안으로 반지름을 줄이거나 폴리라인을 고쳐야 한다고 알린다.
- 도로는 적용 기준과 조건(도로 구분, 지역, 설계속도와 그 출처, 최대 편경사)을 한 줄로 쓴다. 설계속도가 기준표 값이면 "제8조 표 값", 감속했으면 단서 적용과 감속 사유를 남겨야 한다는 notes를 전한다. 근거 조문(제8·19·20·23조, 시행일)도 쓴다.
- 선형 설명에 적용 기준과 조건이 기록되어 나중 검토에서 다시 묻지 않는다는 것을 한 줄로 알린다. 도로가 없으면 "설계 기준 검토 없음"이라고 쓴다.
- option.applicable이 true면 마지막 줄에 "이대로 선형을 만들까요? 반지름을 바꾸려면 'IP2는 600'처럼 말씀해 주세요."라고 묻는다. false면 option.reason을 설명하고 어떻게 고칠지 묻는다.
- 수정안 id(fx-…)와 좌표 목록은 쓰지 않는다.

## 4. 생성 결과 쓰는 법
- 첫 줄: "선형 [이름]을 만들었습니다(길이 ○ m, 곡선 n개). Ctrl+Z 한 번으로 되돌릴 수 있습니다."
- 도로는 recheck를 설계기준 규칙 5절 2·3처럼 쓴다. targetPassed가 false면 미달 항목과 이유를 쓰고 어떻게 할지 묻는다.
- 도로는 "편경사는 아직 계산하지 않았습니다(Civil 3D 편경사 계산 필요)."를 덧붙인다.
- applied가 false면 도면이 바뀌지 않았다고 쓰고 error를 쉽게 설명한다. 폴리라인이 바뀌었다는 오류면 다시 계획할지 묻는다.
- 종단, 코리더, 오프셋 선형은 아직 만들 수 없다. 요청하면 그렇다고 답한다.
