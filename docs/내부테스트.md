# 버전을 유지하는 내부 테스트

수정본을 내 PC에 적용해서 직접 사용하려면 **`내부배포.bat`**을 사용한다. 이 문서의 `내부테스트.bat`은 전체 자동 검사 실행기다. [내부 배포 안내](내부배포.md)를 참고한다.

수정할 때마다 설치 EXE나 배포 버전을 만들지 않는다. **수정 → 내부 빌드·자동 검사 → Civil 3D 수동 확인 → 배포 지시 → 버전 지정·패키징·게시** 순서로 진행한다.

## 1. 내부 빌드와 자동 검사

Civil 3D/AutoCAD를 종료하고 저장소 루트의 `내부테스트.bat`을 실행한다.

- `server/package.json`, 배포 설정과 공개 Release의 버전은 바꾸지 않는다.
- `plugin/bin/Release/net8.0-windows/MyCivil3DMcp.Plugin.dll`과 개발 서버를 빌드한다.
- 서비스·MCP·AI 설치/인증·안전성·관리자·수신/업데이트 회귀 검사와 WPF 구성 검사를 실행한다.
- Autodesk 2025 엔진에서 **실제 플러그인 DLL을 NETLOAD**하고 Initialize, 브리지, 저장소의 개발 Node 서버 시작을 확인한다. 새 도면과 저장 후 다시 연 도면에서 CRUD도 검사한다.
- 결과를 `.package-cache/internal-test/report.json`에 남긴다. 자동 검사가 통과해도 수동 확인은 `pending`이다.

실패한 검사는 배포 버전을 올려 해결하지 않는다. 코드를 수정한 후 내부 검사를 다시 실행한다.

## 2. 실제 Civil 3D에서 기능 확인

전용 테스트 프로필을 사용한다. 기존 설치본이 자동 로드된다면 이 프로필에서 `APPAUTOLOAD`의 현재 값을 기록하고 `0`으로 설정한 뒤 Civil 3D를 재시작한다. 테스트가 끝나면 이 프로필의 원래 값으로 복구한다. 설치본이 이미 로드된 세션에 개발 DLL을 덧붙여 로드하지 않는다. 관리 DLL은 같은 세션에서 교체할 수 없다.

Civil 3D의 `SCRIPT` 명령에서 `.package-cache/internal-test/load.scr`을 선택한다. 도우미는 이미 로드된 설치본 DLL을 감지하면 중단한다. 개발 DLL을 로드하고 `MYC3DCONNECTION`, `MYC3DCHAT`을 실행한다. 연결 출력의 entry가 이 저장소의 `server/build/localService.js`인지 확인한다.

보안 설정이 로드를 막는다면 전용 테스트 프로필의 신뢰할 수 있는 위치에 위 개발 DLL 폴더와 `tests/CivilCrud.Native/bin/Release/net8.0-windows`를 추가한다.

이 흐름의 데이터·연결 파일은 `.package-cache/internal-test` 아래에 둔다. 중앙 전송과 자동 업데이트는 끈다. AI 로그인은 사용자의 기존 CLI 인증을 사용한다. 처음 로그인하거나 CLI를 설치하는 동작은 실제 계정·PC에 적용되며, 질문에는 계정 사용량이 발생할 수 있다.

현재 수정에 맞춰 다음 항목을 실제 팔레트에서 확인한다.

- 팔레트 열기, 연결 상태와 오류 표시.
- Claude·Codex·Gemini 선택, 인증 확인, 질문과 답변, 도면 도구 조회.
- 이번 Gemini 변경: Antigravity 실행, 스트리밍·도구 진행·사용량 표시. 미설치·재로그인·설치 실패는 자동 격리 시나리오 결과도 확인한다.
- 변경 대상 기능의 정상·실패·취소 처리. 도면 변경은 테스트 도면에서 적용·되돌리기·저장 후 재열기까지 확인한다.

수동 확인을 모두 끝낸 담당자만 다음 명령을 실행한다.

```powershell
.\내부테스트.bat -ConfirmManualPass
```

이 명령도 버전을 바꾸거나 배포하지 않는다. 자동 검사 당시와 소스/DLL/서버가 다르면 완료 기록을 거부한다.

## 3. 정식 배포

배포 지시를 받은 뒤에만 `배포하기.bat`을 실행하고 버전을 직접 입력한다. 빈 입력으로 버전을 자동 증가시키지 않는다.

배포 스크립트는 GitHub 확인, 설정 저장, 버전 변경 전에 현재 수정본의 자동·수동 테스트 완료 기록을 검사한다. 기록이 없거나 소스/산출물이 달라지면 버전을 건드리지 않고 중단한다. 버전 번호만 정식 배포 번호로 바꾸는 것은 허용하지만 의존성·스크립트 변경은 다시 검사해야 한다.

`scripts/package.ps1`은 EXE/ZIP 생성과 패키지 검증까지만 한다. 환경 변수에 게시 대상이 있어도 자동 게시하지 않는다. 공개 게시와 다운로드 검증은 `scripts/deploy.ps1`이 수행한다. 내부 테스트 완료가 정식 배포 자체를 의미하지는 않는다.

게시 재시도용 `-SkipBuild`도 현재 테스트 기록과 연결된 EXE의 버전·해시가 일치해야 한다. 이전에 남아 있던 설치 파일을 새 수정본인 것처럼 게시하지 않는다.
