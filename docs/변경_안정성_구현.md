# 도면 변경 안정성과 팔레트 버튼

## 도면과 수정안

- C# DrawingRevisions는 Database마다 고유 drawingId를 부여한다. 같은 파일을 다시 열어도 ID가 다르다.
- 계산 중 모든 브리지 조회에 drawingId/revision 문맥을 전달한다. 페이지나 구간 사이 상태가 달라지면 검토를 중단한다.
- 수정안에는 문맥, 기준·규칙·설정 내용 해시, 만료 시각, 객체/요소 식별 정보를 보관한다.
- 실제 변경 직전 C#에서 도면 잠금 안에서 문맥을 다시 검사한다. 값의 from 검사와 트랜잭션도 유지한다.
- 구버전 수정안은 적용하지 않는다. 캐시 형식은 v2이며, 구버전 캐시는 다시 쓰지 않는다.

## 적용하기 / 되돌리기

1. 답변에서 제안한 수정안은 카드에 표시한다. 자동 변경을 지원하는 카드의 적용하기만 활성화한다.
2. 버튼은 대화 ID와 수정안 ID로 HTTP API를 호출한다. 임의의 설계값이나 CAD 명령은 전달하지 않는다.
3. C#은 작업 ID별 영수증을 보관한다. 동일 작업을 중복 실행하지 않는다.
4. 적용 후 되돌리기를 활성화한다. 원래 도면과 적용 직후 리비전이 그대로일 때만 UNDO 그룹 하나를 취소한다.
5. 되돌리기 영수증이 확인되고 이후 편집이 없으면 적용하기로 같은 수정안을 다시 적용할 수 있다.
6. 버튼 응답 오류 시 작업 영수증을 조회해서 적용/되돌림 상태와 버튼을 복원한다.
7. 대화에서 변경에 동의하는 기존 MCP 흐름도 같은 검증을 거친다.

이후 다른 편집이 있으면 되돌리기를 거절한다. 사용자 편집까지 취소하지 않기 위한 제한이다.
플러그인 영수증은 Civil 3D 세션 범위다. 재시작 후 기존 카드로 이전 작업을 취소하거나 재적용하지 않는다.

## 변경 성공과 재검토 성공

- mutation: applied / rejected / unknown
- drawingChanged: true / false / unknown
- recheck.state: completed / failed / not_required
- assessment: pass / fail / review / incomplete / not_applicable

커밋 뒤 기록·추적·재검토 오류는 변경 성공을 실패로 바꾸지 않는다. 재검토 실패 카드도 되돌리기를 제공한다.
빈 대상·조건 부족·n/a는 통과가 아니다. 전체 항목으로 판정하고 AI 응답 목록만 축약한다.
종단 여러 개의 같은 곡선 번호는 객체 핸들까지 포함해서 구별한다.

## 취소와 응답 유실

AI 중지는 직접 시작한 CLI/MCP 프로세스 트리를 종료한다. 미확인 CAD 작업은 작업 ID별로 취소 표식을
남기거나 영수증을 조회한다. 커밋된 작업은 되돌리지 않고 팔레트에 적용 결과를 제공한다.
변경 요청 전송 뒤 응답을 잃으면 unknown으로 유지한다. 확인 없이 자동 재실행하지 않는다.

## 데이터와 저장

질문 정규화는 소수점·부호·기호·대소문자를 보존한다. 캐시 키에 도면별 지식과 지연 로딩 규칙,
기준표, 모델, 승인된 설정을 포함한다. TCP와 AI 출력은 UTF-8 연속 디코딩을 사용한다.
AI 실행마다 전용 작업 폴더를 만들고 종료 후 정리한다. 공유 추적 파일과 수정안 사용 기록에는
프로세스간 잠금을 사용한다. 잠금이 남아 있으면 강제 탈취하지 않고 작업을 거절한다.

## 확인 방법

server에서 npm run test:safety, npm run test:design, npm run test:tools, npm run test:central을 실행한다.
Civil 3D에서는 다음을 별도 확인한다: 도면 전환 거절, 반지름/PVI/곡선길이 변경, 선형 생성,
버튼 되돌리기·재적용, 다른 편집 이후 되돌리기 거절, 재검토 실패 표시, 중지 버튼.
