# 내부 배포: 수정본을 이 PC에 적용하기

**Civil 3D/AutoCAD를 종료하고 `내부배포.bat`을 실행한다.** 끝나면 Civil 3D를 평소처럼 실행하면 된다. 수정한 팔레트가 자동으로 열린다. NETLOAD, 별도 테스트 프로필, 설치 EXE 생성은 필요 없다.

내부배포는 DLL과 서버를 빌드하고 실행에 필요한 Node·라이브러리를 준비한 뒤, `%APPDATA%/Autodesk/ApplicationPlugins/MyCivil3DMcp.bundle`을 백업·교체한다. 파일 검증이나 교체에 실패하면 기존 설치를 보존·복구한다. 실제 Civil 3D가 실행 중이면 교체하지 않는다.

- 정식 버전 번호·GitHub Release·배포 설정은 변경하지 않는다.
- 전체 자동 테스트를 매번 실행하거나 테스트 완료를 자동 승인하지 않는다.
- 기존 정식 사용자 데이터와 AI 인증은 지우지 않는다. 내부 실행 기록·설정은 `%LOCALAPPDATA%/MyCivil3DMcp/internal-data`를 사용하며, 중앙 전송과 자동 업데이트는 끈다. AI 로그인은 기존 CLI 인증을 이용한다.
- `MYC3DCONNECTION`의 버전에는 `(internal)`이 붙는다. 설치 시각과 원본 저장소는 설치 폴더의 `Contents/internal-deployment.json`에 남는다.
- 반복 내부배포에서도 이전 설치 백업을 유지한다. 복원하려면 Civil 3D를 종료한 뒤 `내부배포.bat -Restore`를 실행한다.

수정 → **내부배포 → 실제 팔레트 사용·수정 반복** → 필요한 자동 검사와 수동 기능 확인 완료 → 배포 지시 후 정식 버전 지정·공개 배포 순서다. `내부테스트.bat`은 자동 검사를 위한 별도 도구다.
