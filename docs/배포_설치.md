# GitHub 설치·업데이트와 Google Drive 데이터 수신

사용자는 https://github.com/wocl123/civil3d-mcp/releases/latest 에서 `MyCivil3DMcp-버전-win-x64.exe`를 다운로드한다. Civil 3D와 AutoCAD를 종료한 뒤 실행하고 설치 마법사의 [설치]를 누른다. Google 로그인, Drive 앱 설치, 폴더 공유, 데이터 경로 설정은 필요 없다. AI 계정 로그인은 별도로 필요하다.

설치 EXE는 Inno Setup으로 만든다(`scripts/installer.iss`). 사용자별 설치라 관리자 권한이 필요 없고, `%APPDATA%\Autodesk\ApplicationPlugins\MyCivil3DMcp.bundle`에 설치한다. 다시 설치하면 이전 버전 파일을 지우고 새로 넣는다. 제거는 Windows [설정 → 앱]에서 "My Civil 3D MCP"를 지운다. 사용자 데이터(`%LOCALAPPDATA%\MyCivil3DMcp`)는 제거해도 남는다.

0.1.7 이하는 직접 만든 압축 해제 EXE가 숨긴 PowerShell을 실행하는 구조라, 다운로드 때 Defender가 `Trojan:Win32/Wacatac.B!ml`로 오탐했다. 0.1.8부터 Inno Setup으로 바꿨다. 0.1.7 이하의 자동 업데이트는 새 EXE를 실행하지 못하므로(예전 `--extract` 호출은 바로 실패로 끝난다) 0.1.8은 한 번 직접 받아 설치해야 한다.

기존 Drive 배포 설치본은 새 GitHub 채널을 알지 못하므로 새 EXE로 한 번 설치해야 한다. 설치 시 기존 기록과 AI 설정을 유지한다.

## 관리자 배포

관리자 빌드 PC에는 Node.js, .NET 8 SDK, Civil 3D 2025 참조 DLL 및 GitHub CLI가 필요하다. `gh auth login`은 관리자만 한 번 실행한다. Drive for Desktop은 비공개 수집폴더를 관리자 PC에서 읽을 때 필요하다.

`배포하기.bat`을 실행하고 버전을 입력한다. 최초 설정은 `.drive-deploy.json`에 보관한다. 기존 관리자 메일·수신 URL·비공개 수집 경로를 유지하고 GitHub 배포 저장소를 추가한다. 관리자가 ZIP을 전달하거나 팔레트에서 배포하지 않는다.

1. 수신 웹앱 준비 상태를 확인한다.
2. 새 버전 빌드, 회귀 검사, 설치·복구 검사 후 EXE와 RSA 서명을 만든다.
3. EXE에 올바른 GitHub 채널과 데이터 수신 URL이 들어 있는지 검사한다.
4. 공개 배포 전용 저장소에 초안 Release를 만들고 EXE, .sig, .sha256, 서명된 latest.json을 모두 올린 뒤 공개한다.
5. 로그인 없는 실제 다운로드와 로컬 EXE의 일치를 확인한다.

소스와 Release는 공개 저장소 `wocl123/civil3d-mcp`를 함께 사용한다. Release에는 EXE와 검증 파일만 게시한다. 소스 커밋·푸시는 배포 작업에 포함하지 않는다. 공개 Release 변경 방지를 활성화하며, 게시된 버전은 덮어쓰지 않고 새 버전으로 배포한다. ZIP은 패키징·복구 검사에 사용하는 내부 산출물이며 사용자 Release에는 게시하지 않는다.

예시:
```powershell
.\배포하기.bat -Version 0.1.6 -GitHubRepo wocl123/civil3d-mcp
```

## 자동 업데이트

서비스 시작 20초 후, 이후 6시간마다 공개 GitHub 최신 Release를 확인한다. 관리자 토큰이나 사용자 GitHub 로그인을 사용하지 않는다. GitHub 저장소·버전·파일 URL을 확인하고 기존 설치에 들어 있는 공개 키로 latest.json 및 EXE의 RSA 서명, 크기와 SHA-256을 검증한다. 다운로드는 허용된 GitHub 호스트만 사용한다.

검증된 업데이트는 Civil 3D 종료 후 설치한다. 오류·오프라인·GitHub 요청 제한·미완성 Release이면 설치하지 않고 다음 점검 때 재시도한다. 데이터 보내기 설정을 꺼도 업데이트는 별도로 동작한다. 기존 Drive 업데이트 코드는 구버전 호환용으로 남지만 GitHub 채널이 있으면 GitHub를 우선한다.

Windows 게시자(Authenticode) 서명은 아직 없다. RSA 업데이트 서명과 별개이므로 "Windows의 PC 보호" 경고가 나올 수 있다([추가 정보 → 실행]). 자동 업데이트는 서명을 확인한 EXE를 창 없이(`/VERYSILENT`) 실행한다. 첫 설치는 관리자가 안내한 정확한 배포 저장소에서 받아야 한다.

## AI 사용 한도 안내

0.1.7부터 Claude·Codex·Gemini 실행 실패의 표준 출력 JSON과 오류를 확인해 사용 한도, 인증, 결제, 연결 오류를 구분한다. 한도 소진을 다시 로그인하라는 안내로 처리하지 않는다. 복구 시각이 제공되면 PC의 현지 시각과 남은 대기 시간을 표시한다. 복수의 0% 구간이 확인되면 각 구간과 확인된 가장 늦은 복구 시각을 안내한다. 시간이 제공되지 않으면 확인 불가로 표시한다. 팔레트 하단의 한도 정보도 실패 직후 갱신하며, 성공하거나 알려진 재설정/기록 유효 시간이 지나면 이전 실패 표시를 해제한다. Gemini 인증 확인 중 한도 오류도 로그인 실패로 처리하지 않는다. Windows 팔레트의 실제 표시와 현재 계정의 소진 상태는 설치 후 확인한다.

## 데이터 수신 및 관리자 운영

사용자 로컬 기록은 기본적으로 `%LOCALAPPDATA%\MyCivil3DMcp\data`에 저장한다. 서비스가 비식별 처리한 기록과 지식 후보를 관리자 Apps Script 웹앱에 자동 전송한다. 웹앱이 비공개 `MyCivil3DMcp-data` 폴더에 사용자별로 저장한다. 전송 상태는 팔레트의 /중앙에서 확인하며 보내기를 끄거나 켤 수 있다.

관리자 PC나 `관리자실행.bat`이 실행 중일 필요는 없다. `관리자실행.bat`은 Drive에 이미 수신된 데이터를 수집·검토하고 지식을 승인할 때 실행한다. 관리자 PC에서 사용자용 설치를 테스트해도 같은 자동 수신 경로를 사용한다.

비공개 데이터 폴더를 공개 배포폴더 안에 넣거나 사용자와 공유하지 않는다. 웹앱 설정/보안은 `scripts/google-ingest/README.md`와 `docs/Drive_보안점검.md`를 참고한다. GitHub로 바꿔도 데이터 수신 권한과 비식별 처리의 보안 한계는 별도로 관리해야 한다.

## 검증

패키지 빌드는 서비스·MCP·기억·지식·안전성, 구버전 Drive 호환, Google 로그인 없는 등록·전송·재시도·사용자 격리, 관리자 수집과 승인 지식 반환을 검사한다. GitHub 채널은 서명 위조·다른 저장소/태그·외부 리다이렉트·초과 크기·요청 제한·미완성 Release를 검사한다. 실제 EXE의 설치·업데이트·복구와 서명 변조 거부를 임시 경로에서 검사한다. Civil 3D 팔레트 UI는 실제 사용자 PC에서 확인해야 한다.
