# 코드 스타일 (가독성 규칙)

목표: 처음 보는 개발자가 위에서 아래로 한 번 읽으면 흐름이 보이는 코드.
들여쓰기·줄끝 같은 모양은 루트의 `.editorconfig`가 맡고, 이 문서는 사람이 지켜야 할 규칙만 적는다.

## 1. 한 줄에는 한 가지 일만

```csharp
// 나쁨
if (planned.Radius is not double radius || radius <= 0) continue;

// 좋음
double radius = planned.Radius ?? 0;
if (radius <= 0)
{
    return null;
}
```

- `if`·`for`·`foreach`·`while` 본문은 한 줄이어도 중괄호로 감싸고 다음 줄에 쓴다.
- `is not T x || ...`처럼 패턴 변수 선언과 조건을 한 줄에 섞지 않는다. 값을 먼저 꺼내고 조건은 따로 쓴다.

## 2. 조건은 이름을 붙여서

조건이 두 개 이상 엮이면 `bool` 변수에 이름을 붙인다. 이름이 곧 주석이 된다.

```csharp
bool hasCurvePerInnerPoint = request.Curves.Count == request.Points.Count - 2;
if (request.Points.Count < 2 || !hasCurvePerInnerPoint) { ... }
```

여러 줄로 나눌 때는 `&&`·`||`를 줄 앞에 둔다.

## 3. 단계 사이는 빈 줄

찾기 → 검사 → 바꾸기 → 결과처럼 단계가 바뀌면 빈 줄을 넣는다. 블록(`}`) 뒤에도 빈 줄을 둔다.

## 4. 긴 메서드는 단계별로 나눈다

메서드가 한 화면(약 40줄)을 넘거나 `// ── 단계` 주석이 여러 개 붙으면 단계마다 작은 메서드로 뽑는다.
메서드 이름은 하는 일을 그대로 쓴다: `EnsureNameIsFree`, `AddFixedLines`, `FindPolyline`.

## 5. 줄 길이 120자

- 120자 안에 들어가면 한 줄로 쓴다. 억지로 쪼개지 않는다.
- 넘치면 괄호 뒤에서 한 번 줄을 바꾸고 인자를 이어서 쓴다. 인자를 한 줄에 하나씩 세로로 늘어놓지 않는다.
  ```csharp
  AlignmentArc arc = alignment.Entities.AddFreeCurve(
      lineBefore, lineAfter, radius, CurveParamType.Radius, false, CurveType.Compound);
  ```
- LINQ·메서드 체인이 넘치면 `.`마다 줄을 바꾼다.
- 긴 삼항 연산자(`a ? 긴식 : 긴식`)는 `if`/`else`로 바꾼다.

## 6. 동작은 바꾸지 않는다

가독성 정리는 동작이 같아야 한다. 정리한 뒤에는 꼭 확인한다:

- 플러그인: `cd plugin && dotnet build`
- 서버: `cd server && npm run build && npm run test:design` (계산을 건드렸으면 다른 test:* 도)
