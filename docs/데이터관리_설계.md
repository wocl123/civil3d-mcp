# 데이터 관리 설계

2026-10-06. 이 PC의 데이터와 중앙 서버로 모으는 데이터를 어떻게 저장하고, 가리고, 보내고, 지우는지 정한다.
코드를 바꿀 때는 이 문서도 같이 고친다.

## 1. 원칙

1. **한 곳에 둔다.** 사용자 데이터는 `%LOCALAPPDATA%\MyCivil3DMcp\data` 한 곳에만 둔다(`MY_CIVIL3D_DATA_DIR`로 바꿀 수 있음).
   설치 폴더에는 두지 않는다. 예전처럼 "설치 폴더에 못 쓰면 다른 곳"으로 갈라지는 일을 없앤다.
2. **원문은 이 PC를 떠나지 않는다.** 질문·답변 원문, 도면 파일, 도면 이름, 경로, 좌표, 핸들, 객체 이름, 사용자·PC 이름은 보내지 않는다.
3. **허용 목록으로 만든다.** 보내는 기록은 정해진 필드만 골라 새로 만든다. 원래 기록에서 지우는 방식(차단 목록)이 아니다.
   서버도 같은 허용 목록으로 다시 거른다(모르는 필드는 버린다).
4. **마지막 검사에서 걸리면 보내지 않는다.** 묶음(패키지)을 보내기 직전에 경로·메일·도면 이름 같은 흔적을 한 번 더 찾는다.
   걸리면 `outbox/blocked`에 사유와 함께 남기고 보내지 않는다.
5. **사람이 승인해야 모두에게 간다.** 다른 사용자 데이터로 만든 제안(통계)과 지식 후보는 검토자가 승인해야 중앙 지식이 된다.
   승인 전 내용은 어떤 AI 프롬프트에도 들어가지 않는다.
6. **사용자는 할 일이 없다.** 기록, 비식별 처리, 전송, 재시도, 중앙 지식 받기, 정리는 모두 자동이다.
   서버가 꺼져 있어도 PC에 쌓아 두었다가 연결되면 보낸다.
7. **기한이 있다.** 모든 데이터에 보관 기한이 있다(§7).

## 3. 보내는 기록(허용 목록, schema 1)

시각은 시간 단위로 줄인다(`2026-10-06T13`). 오류는 원문 대신 실패 안내의 종류(`errorKind`)만 보낸다.
모든 기록에 그 기록을 남길 때의 프로그램 버전(`appVersion`, 예: `0.1.0`, 개발 폴더면 `dev`)을 붙인다. 업데이트 전후 기록이 한 묶음에 섞여도 구분되고, 중앙 보고서(`/검토 보고`)에 버전별 설치 수·질문 수·실패율이 나온다.

| type | 필드 | 쓰임 |
|---|---|---|
| `turn` | kind, provider, model, ms, cached, tools[], usage, counts{recorded, candidates, fixes, applied}, errorKind | 느린 질문, 실패, 토큰 |
| `tool` | tool, ms, ok, outputChars, images, errorKind | 도구별 실패율·속도 |
| `change` | state, source(create/fix), check, changes[{kind, property, before, after}], curves, errorKind | 수정안이 실제로 적용되는지 |
| `modification` | source, objectKind, property, aiValue, userValue, outcome, ageHours, conditions{designSpeed, roadClass, region, criteria} | **사람이 AI 결과를 고쳤는지(학습 신호)** |

`check`는 코드가 기준표에서 만든 문구다(예: `제19조 최소 평면곡선 반지름`). 측점, 핸들, 선형 이름, 수정안 제목은 보내지 않는다.

지식 후보는 따로 보낸다. 보내는 필드는 localId, title, content, parameter, provider, 날짜다. 근거(사용자 말 인용)는 보내지 않는다.
content에 도면 이름 같은 가릴 낱말이 있으면 `<이름>`으로 바꾼다. 경로는 `<경로>`로 바꾼다.

### 마지막 검사(패키지 전체 문자열)

- 드라이브 경로(`C:\`, `D:/`), UNC 경로(`\\server`), 메일 주소, `.dwg`/`.dxf` 파일 이름
- Windows 사용자 이름, PC 이름
- `terms.json`의 낱말(3자 이상)

하나라도 걸리면 그 패키지는 보내지 않는다. 서버도 같은 규칙으로 다시 검사하고, 걸리면 받지 않는다(422).

## 4. 사용자 수정 추적

AI가 도면을 바꾸면 그 값을 `tracking\`에 남긴다. 대상은 선형 생성과 수정안 적용이다.

| 대상 | 읽는 곳 | 찾는 기준 |
|---|---|---|
| 생성 선형의 곡선 반지름·완화곡선 길이 | alignment.section `elements` | 곡선 그룹 번호 |
| 수정안: 원곡선 반지름 | 위와 같음 | 수정안 대상의 곡선 번호 |
| 수정안: PVI 표고 | profile.section `pvis` | PVI 측점 |
| 수정안: 종단곡선 길이 | profile.section `curves` | PVI 측점 |

- **언제 확인하나:** 팔레트 질문이 시작될 때와 동기화 주기마다 확인한다. 열린 도면이 같고, 도면 revision이 지난 확인 때와 다를 때만 읽는다.
- **결과 종류:**
  - `modified`: 값이 바뀜. 바뀔 때마다 기록한다.
  - `deleted`: 객체가 없어짐.
  - `restructured`: 곡선 개수가 달라져 비교할 수 없음.
  - `kept`: 14일 동안 그대로.
- **기록이 끝나는 때:** `deleted`, `restructured`, `kept`가 되면 추적을 끝낸다.
- **알 수 없는 것:** 사용자가 도면을 저장하지 않고 닫으면 알 수 없다. 이 기록은 "그 사이에 고친 적이 있다"는 뜻이지, "최종 도면이 그렇다"는 뜻이 아니다.

## 5. 설정값(승인된 관행 → 코드)

관행 중에는 숫자로 바꿔 코드가 직접 쓸 수 있는 것이 있다. 이런 것은 정해진 설정값으로 둔다.

| 키 | 뜻 | 정하지 않았을 때 | 허용 값 |
|---|---|---|---|
| `alignment.radiusStep` | 평면곡선 반지름 올림 단위(m) | 선형 계획 5, 수정안 1 | 1, 5, 10, 50, 100 |
| `alignment.spiralStep` | 완화곡선 길이 올림 단위(m) | 1 | 1, 5, 10 |
| `profile.curveLengthStep` | 종단곡선 길이 올림 단위(m) | 1 | 1, 5, 10, 20 |

- **우선순위:** 이 PC에서 승인한 값 > 중앙 값 > 기본값.
- **화면 표시:** 기본값이 아닌 값을 쓰면 계획·수정안의 notes에 어디서 온 값인지 적는다.
- **AI가 제안하는 경우:** AI가 일반 관행을 기록할 때, 관행이 위 키에 해당하면 `parameter: {key, value}`를 붙인다. 허용 값이 아니면 버린다.
- **답변 캐시:** 설정값이 바뀌면 답변 재사용 키도 바뀐다.

## 6. 중앙 서버

`central/` 폴더에 있다. 설치·주소 변경·이전은 [중앙서버_설정_가이드.md](중앙서버_설정_가이드.md). Node 20, 외부 패키지 없음. 저장은 파일(JSON·JSON Lines)이다.
규모가 커지면 `store.ts`만 DB로 바꾼다.

| API | 누가 | 하는 일 |
|---|---|---|
| `POST /v1/enroll` | 설치 | 가입 키 + 익명 ID → 토큰(서버에는 해시만 저장) |
| `POST /v1/packages` | 설치 | 비식별 패키지. 같은 ID는 한 번만 받음 |
| `POST /v1/candidates` | 설치 | 지식 후보. 같은 (설치, localId)는 한 번만 받음 |
| `GET /v1/official?since=n` | 설치 | 승인된 중앙 지식과 설정값(바뀌었을 때만 본문) |
| `GET /v1/review` | 검토자 | 후보 묶음(지지한 설치 수) + 통계 제안 |
| `POST /v1/review/decide` | 검토자 | 승인(문구 고칠 수 있음) / 반려(사유 필수) / 철회 |
| `GET /v1/report` | 검토자 | 실패·느린 도구, AI 결과 유지율 |

- **인증:** 설치마다 Bearer 토큰을 쓴다. 검토자는 `X-Reviewer-Key`를 쓴다. 키는 서버를 처음 시작할 때 만들어 `config.json`에 둔다.
- **HTTPS:** 서버는 HTTP로 뜬다. 인터넷에 열 때는 HTTPS 프록시를 앞에 둔다. 클라이언트는 localhost나 사설 IP가 아닌 http 주소이면 경고한다.

### 통계 자동 제안("다른 사용자에게서 배우기")

- **후보 묶기:** 띄어쓰기와 문장부호를 뺀 내용이 같은 후보를 한 묶음으로 본다. 지지 = 서로 다른 설치 수다.
- **설정값 제안:** `modification`(modified) 중 같은 속성에서 아래를 모두 만족하면 `alignment.radiusStep = s`를 제안한다.
  - 사람이 고친 값이 s의 배수다.
  - AI 값은 s의 배수가 아니었다.
  - 이런 경우가 그 속성 수정의 80% 이상이다.
  - 경우가 5건 이상이다.
  - 서로 다른 설치 2곳 이상에서 나왔다.
  - 기준(`minInstalls`, `minCases`)은 서버 `config.json`에 있다.
- **유지율 보고:** AI가 만든 값이 그대로 남았는지(kept), 고쳐졌는지(modified), 지워졌는지(deleted)를 보고한다. 이 결과는 규칙 개선의 근거다.

제안은 검토자의 `/검토` 목록에 지지 수와 함께 나온다. 승인하면 중앙 지식 버전이 1 오르고, 모든 PC가 다음 동기화에서 받는다.

## 8. 동기화 주기(로컬 서비스)

동기화는 서비스 시작 5초 뒤, 10분마다, 질문이 끝나고 10초 뒤에 돈다. 한 번에 하나만 돈다. 순서는 아래와 같다.

1. 수정 추적 확인(열린 도면)
2. 새 로그를 읽어 비식별 패키지를 만들고, 마지막 검사를 거쳐 `outbox`에 넣음(서버 연결과 무관)
3. 서버가 연결돼 있으면: 패키지 보내기 → 후보 보내기 → 중앙 지식 받기
