# 생성·수정 코드 리팩토링

버전 0.1.16을 유지한다. 동작 변경이나 새 기능 추가 없이 작업 연결, 도구 배치와 공통 입력 규격을 정리한다. Git 커밋·푸시와 공개 Release는 수행하지 않는다.

## 변경

- `CivilOperationHandlers`에 도면 작업 109개의 검증·적용 메서드를 한 쌍으로 등록한다. `CivilPlans`의 중복 switch, 접두어 분기, 중첩 삼항식 및 반복 Commit을 제거한다. `CivilPlans`는 미리 보기 지문 비교와 트랜잭션 관리를 맡는다. 연속 작업·일괄 작업·화면 명령·기본 대화형 명령은 기존 문서 컨텍스트 경로를 유지한다.
- `thirdStageTools.ts`는 등록 순서를 연결하는 작은 파일로 줄이고 실제 도구는 선형 편집, 필지, 속성 세트, 연속 작업, 지표면 분석, 설계 주석의 6개 모듈로 나눈다.
- `civilToolSchemas.ts`에서 문자열·유한 숫자·좌표·핸들·대상 배열·도구 annotation을 공유한다. 도구별 기본값·설명·동의 문구는 보존한다.
- `ParcelComInterop`으로 설치된 Civil COM 호출을 분리한다. 필지의 경계 검증·위상 검사·트랜잭션 정책과 COM 초기화가 서로 분리된다. COM 생성 순서와 호출 인수는 유지한다.
- 속성 정의의 스키마 직렬화는 `PropertySetChanges.Schema` 하나로 통일하고 단순 전달 메서드를 제거한다.

## 검증

변경 전후 확장 MCP 도구 45개의 이름, 등록 순서, 설명, annotation 및 입력 JSON 스키마를 비교한다. 일반 회귀는 `내부테스트.bat`의 서버 검사, 실제 Autodesk NETLOAD·CRUD·Undo·저장 후 재열기로 확인한다. 필지 COM은 동일 빌드 내부배포 후 `server/scripts/native-parcel-gui.mjs`로 실제 Civil 3D에서 별도 검사한다.

검사 결과는 `.package-cache/internal-test/report.json` 및 `.package-cache/native-parcel-*` 기록을 따른다. 자동 검사 통과와 실제 팔레트 수동 확인 대기는 구분하며, 이번 정리로 기존 정지 생성·기준 기반 편경사 자동 산정 등의 지원 범위가 달라지지 않는다.
