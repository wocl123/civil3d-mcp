# 누락 기능 2차 확장

후속 구현은 [3차 확장 기록](추가확장_3차.md)을 따른다. 아래는 2차 기록이다.

버전 0.1.16을 유지한다. 개발 소스와 설치본의 일치는 내부배포 이후 별도로 검증한다. 자동 검사 상태는 `.package-cache/internal-test/report.json`, 설치 기록은 `.package-cache/internal-deploy/`를 따른다. 실제 팔레트 수동 확인은 대기다. Git 커밋·푸시 및 공개 Release는 하지 않는다.

## 이번 직접 API 확장

| 분야 | 구현 범위 | 제한 |
| --- | --- | --- |
| 횡단 | 기존 추출선 측점·좌우 폭·정점·이름·측점 고정 편집, 일정 간격 생성 | 최대 200개, 꺾인 선은 정점 편집, 중심 정점 이동 불가, 방정식 선형의 자동 측점/폭 처리 거부 |
| 코리더 | 구간 분할·병합·삭제, 형상선 기준선, 현재 도면에 셰이프 코드별 솔리드 추출 | 추가 측점·오프셋 기준선·재지정 포함 구간 분할은 기본 명령 사용. 자동 병합은 타깃 없는 같은 표준횡단의 연속 구간, 앞 설정 유지 |
| 서브어셈블리 | 실제 입력 매개변수·단위·정수 선택지 조회, double/integer/boolean/string 입력값 편집, 관련 코리더 재작성 | 읽기 전용·출력 전용·없는 키·잘못된 선택지 거부. 모든 형상의 타당성이나 설계 기준 충족을 보증하지 않음 |
| 압력 관로 런 | 실제 카탈로그 규격으로 생성, 분할·병합, 종단 추종 | 생성 경로는 열린 XY 직선 세그먼트 폴리선, 원본 보존. 종단은 해당 경로 선형 소속, 오프셋·추종 여부 명시 |
| 집수구역 | 그룹 생성, TIN·명시 폐합 경계로 생성, 이름·그룹·유출계수·Curve Number 편집 | 유출점 쓰기 및 흐름 경로 상세 설정은 기본 대화형 작업. 배수 해석 수행과 구별 |
| 선형 | 측점 방정식 전체 교체·제거, 원시 후측점·전측점·증가/감소 지정 | 기존 전체 목록 확인 필요. 형상은 유지하지만 종속 객체 측점 표기에 영향. 주석 편집은 2025 직접 API 범위 밖 |

새 MCP 도구 5개: `plan_alignment_station_equations`, `list_pressure_runs`, `plan_pressure_run`, `list_catchments`, `plan_catchment`. 앞서 추가한 26개 도구를 합쳐 확장 도구는 31개이며, 기존 `plan_section_design`과 `plan_corridor_design`의 지원 작업도 늘렸다.

## 추가 기본 대화형 연결

설치된 CUI의 명령을 확인하여 연결 선형·선형 배치, 집수구역 생성·편집·라벨, 관망 간섭 검사, 코리더 구간/솔리드 추출, 압력 관로 런 배치·분할·병합·종단·재연결, 참조 템플릿, 속성 세트 정의, 철도 선형·레일·캔트·플랫폼 작업을 연결했다.

기본 명령 연결은 사용자 입력이 필요하다. 명령 접수를 객체 생성·설계·출력 완료로 표시하지 않는다. 특히 간섭 검사는 2025 공개 .NET 형식에 생성 API가 없어 이번에는 기본 검사 명령 경로로 제공한다. 필지·정지·편경사의 완전 자동 설계, 임의 선형 IP/요소 재구성, 속성 세트 값의 자동 편집은 이번 직접 API 확장 범위에 포함하지 않는다.

## 검증과 속도 보완

실제 Autodesk 엔진 검사에 기존 추출선 편집·단일 Undo·오래된 계획 거부, 일정 간격 생성·이름 충돌, 구간 처리, 실제 기본 서브어셈블리 폭·선택지 검증, 형상선 기준선, 실제 도로 단면의 솔리드 추출, 집수구역 생성·속성·그룹 Undo, 관로 런 생성·분할·병합·종단 추종, 측점 방정식·Undo 및 저장 후 재열기를 추가했다. 모든 도면/카탈로그 조합과 UI 작업 흐름의 검증을 의미하지 않는다.

서브어셈블리 조회는 요청한 페이지의 매개변수만 읽고 한 계획 내 검증 자료를 재사용한다. 집수구역은 그룹 목록과 경계 목록을 나눠 경계를 페이지 단위로 읽는다. 일정 간격 생성은 여러 AI/도구 왕복 없이 한 계획으로 실행한다.

전체 내부 검사를 통과한 결과물만 이 PC에 내부배포한다. 일반 Civil 3D 실행으로 수정본을 사용하며 NETLOAD는 필요 없다. 팔레트에서 실제로 확인하기 전에는 내부 테스트 전체 완료로 보고하지 않는다.
