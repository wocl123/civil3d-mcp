# Civil 3D 생성·수정 자동화 4차

버전 0.1.16을 유지한다. Git 커밋·푸시와 공개 Release는 수행하지 않는다. 이번 범위는 기존 대화형 경로 중 직접 처리할 수 있는 필지·편경사·수동 속성 정의를 자동화하고 연속 처리의 호출 횟수를 줄이는 것이다. Civil 3D의 모든 대화형 기능을 자동화했다는 뜻은 아니다.

| 분야 | 직접 처리 | 지원 범위와 제한 |
| --- | --- | --- |
| 필지 | `list_parcels`, `plan_parcel` | 닫힌 단순 직선 XY 폴리선에서 새 Site와 실제 Civil 필지 1개 생성, 이름·주소·taxId 편집. 원본 유지. 기존 Site 분할·면적 최적화 제외 |
| 편경사 | `plan_superelevation` | 사용자 곡선 초기화, Manual 측점 추가·삭제, 실제 차로·길어깨 경사 편집, 최대 200행 표 일괄 입력. 미지정 값 유지. 비율 0.06=6%. 기준 파일에 따른 자동 산정 제외 |
| 속성 정의 | `plan_property_definition` | 객체 기반 수동 Text/Integer/Real/TrueFalse 정의 생성·추가, 기본값 지정, 기존 부착 객체 동기화와 값 보존. 형식 변경·삭제·자동/수식 속성 제외 |
| 연속 처리 | 기존 `plan_civil_workflow` 확장 | 객체 → 정의 → 부착 → 값 입력을 한 계획으로 처리. definition도 앞 단계 handle 참조. 전체 롤백 검증 후 적용, 실패 시 전체 취소 |

새 MCP 도구 4개가 추가되어 앞선 확장 41개와 합해 45개다. 연속 처리는 AI가 단계마다 결과 핸들을 받아 다음 도구를 재호출하는 횟수를 줄인다. 편경사 setTable도 측점별 호출을 한 번으로 묶는다. 전체 AI 응답 시간에 대한 새로운 속도 측정치는 산출하지 않는다.

## API와 검증

설치된 Civil 3D 2025의 AeccDbMgd, AecPropDataMgd, Autodesk.AECC.Interop.Land와 동봉 COM 예제를 확인했다. 필지는 IAeccParcelSegments.AddFromEntity, 편경사는 SuperelevationCurveCollection 및 SuperelevationCriticalStation.SetSlope, 속성 정의는 PropertySetDefinition/PropertySet.Synchronize를 사용한다.

Core Console에서는 Civil COM 서버를 초기화할 수 없다. 따라서 속성 정의·편경사·연속 처리와 기존 회귀는 `내부테스트.bat`으로, 필지는 `node server/scripts/native-parcel-gui.mjs`로 실제 Civil 3D를 실행해 검사한다. GUI 검사에서는 이미 로드한 플러그인이 현재 빌드와 SHA-256이 같을 때 그 DLL을 사용한다. 다르면 중단하고 내부배포가 필요하다고 알린다. 개발 DLL과 설치 DLL을 함께 로드하지 않는다. 전용 프로필을 사용하고 종료 후 기존 시작 프로필을 복원한다.

자동 검사는 생성·값 보존·미리 보기의 무변경·실패 거절·외부 트랜잭션 롤백·Undo·저장 후 재열기를 포함한다. 결과는 `.package-cache/internal-test/report.json` 및 `.package-cache/native-parcel-*/parcel-automation.json`, `parcel-reopen.json`을 따른다. 실제 팔레트의 수동 기능 확인은 별도이며 확인 없이 완료 처리하지 않는다.

## 남는 제약

설치된 .NET Grading 클래스와 COM 타입 목록에서는 정지 객체를 생성하는 공개 메서드를 확인하지 못했다. 정지 생성·인필·토량 균형은 기존 Civil 기본 대화형 기능으로 남는다. 복잡한 필지 분할, 기준 파일을 이용한 편경사 산정, 복합 선형 구속조건 전체 편집, 자동 유역 산정, 자동·수식 속성 스키마는 이번 자동 처리에 포함하지 않는다. 명령 실행 접수를 설계 완료로 보고하지 않는다.
