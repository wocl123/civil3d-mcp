### 2.1 Defender 오탐과 Inno Setup 전환 (0.1.8)

**문제와 원인**
- 0.1.5와 0.1.7 EXE를 내려받을 때 `Trojan:Win32/Wacatac.B!ml`, `Sabsik.FL.A!ml`로 차단됐습니다.
- 원인은 직접 만든 csc 자체 압축 해제기(`scripts/Installer.cs`, 삭제됨)였습니다. 이 해제기가 숨긴 PowerShell을 `-ExecutionPolicy Bypass`로 실행했습니다.

**해결: Inno Setup 6.7.3으로 교체**
- ISCC 위치: `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`
- CI에서는 `choco install innosetup`으로 설치합니다.

**`scripts/installer.iss` 설정** (UTF-8 BOM 파일)
- AppId: `{E49DD37D-13B7-4DA8-A616-85109188D819}`
- 사용자 단위 설치이고(`PrivilegesRequired=lowest`), 한국어 마법사를 씁니다.
- 설치 위치: `{userappdata}\Autodesk\ApplicationPlugins\MyCivil3DMcp.bundle`
- 제거 정보 위치: `UninstallFilesDir={app}.uninstall`
- `[InstallDelete]`로 기존 `{app}\Contents`와 `{app}.backup-*`를 지웁니다.
- team.json은 `{param:DataDir|{localappdata}\MyCivil3DMcp\data}`에 씁니다.
- `/Sandbox=1`을 주면 CAD 실행 검사와 레지스트리 등록을 건너뜁니다(테스트용).
- `--extract`로 실행되면 바로 종료합니다. 0.1.7 이하의 예전 자동 업데이트가 이렇게 부릅니다.
- 설치 전에 WMI로 acad.exe와 번들 node.exe가 실행 중인지 검사합니다.

**함께 만들거나 바꾼 스크립트**
- `scripts/build-installer.ps1`: EXE를 빌드합니다.
- `scripts/installer-sandbox.mjs`: `sandboxInstall(exe, root)`
  - root 폴더를 먼저 만들어야 합니다. /LOG 폴더가 없으면 Inno가 코드 1로 끝납니다.
  - 인자는 `/DIR="..."` 형태로 `windowsVerbatimArguments`와 함께 넘깁니다.
- `install-exe.ps1`: RSA 서명을 확인한 뒤 `/VERYSILENT /DIR /DataDir /LOG`로 실행합니다.
- 다음 파일들은 `--extract` 대신 sandboxInstall을 씁니다:
  - `package.ps1`
  - `scripts/github-publish.mjs`
  - `scripts/drive-publish.mjs`
  - `server/scripts/drive-publish.mjs`
- 시험: `server/scripts/installer-exe.mjs`

**결과**
- EXE 크기가 약 42MB에서 27MB로 줄었습니다.
- 내려받은 v0.1.8 파일은 검사에서 깨끗했습니다.
- 지금은 SmartScreen의 "알 수 없는 게시자" 경고만 나옵니다. 사용자에게는 ⋯ → 유지 → 자세히 표시 → 그래도 계속 순서로 안내했습니다.

**업데이트 주의**
- 0.1.7 이하가 설치된 PC는 0.1.8을 **직접 받아 설치해야** 합니다. 자동 업데이트로는 넘어가지 않습니다.

**코드 서명 (미결정)**

### 2.2 Drive 날짜 폴더 (`553858b`)

**저장 위치**
- `Code.gs`가 받은 묶음을 `packages/<YYYY-MM-DD>/`에 저장합니다.
- 지식 후보는 `candidates/<YYYY-MM-DD>/`에 저장합니다.

**날짜를 정하는 방법**
- 묶음은 `intakeDay()`로 정합니다. 묶음 `createdAt`의 시각(시간 단위)을 한국 시간 날짜로 바꿉니다.
- 후보는 `item.at`을 날짜로 씁니다.
- 응답을 잃어 다음 날 다시 보내도 같은 폴더로 가므로 중복되지 않습니다.

**관리자 쪽 읽기**
- `server/src/drive/driveFolders.ts`의 `datedJsonFiles()`를 씁니다.
- `server/src/admin/adminSync.ts`가 예전 평평한 구조와 날짜 폴더를 모두 읽습니다.

**적용 상태**
- 사용자가 Apps Script에 Code.gs를 붙여 넣고 재배포했습니다. URL은 같습니다.
- `Validation.gs`는 바뀌지 않았습니다.

### 2.3 AUTH_FAILED 자동 재등록 (`85e3f24`)

**문제**
- 관리자가 Drive에서 사용자 폴더(`.receiver-auth.json` 포함)를 지웠습니다.
- 그 뒤로 웹앱이 `AUTH_FAILED`로 거절해 전송이 멈췄습니다.

**수정: `server/src/ingest/memberSync.ts`**
- `Rejected(code)` 오류 클래스를 추가했습니다.
- `register()`와 `sendWithRegistration()`을 추가했습니다. AUTH_FAILED가 나면 **같은 토큰**으로 한 번 다시 등록하고 재시도합니다.
- 다른 토큰으로 가로채려는 시도는 여전히 AUTH_FAILED가 납니다. 시험에 이 경우도 넣었습니다.

**배포 상태**
- 이 수정은 **0.1.9에 들어가야 합니다(아직 미배포).**
- 그 전까지는 Drive에서 사용자 폴더를 지우지 말아야 합니다.

## 7. 알아 둘 함정

**설치 EXE와 배포**
- Inno Setup은 /LOG 폴더가 없으면 코드 1로 실패합니다. 반드시 먼저 `mkdir`합니다.
- ISCC는 PATH에 없습니다. `scripts/build-installer.ps1`이 찾아 줍니다.

**도구 사용**
- Write 도구에 `\uFEFF`를 쓰면 실제 BOM 문자가 됩니다. 정규식은 `/^\s+/`를 쓰면 안전합니다.
- bash의 `node -e`나 Python heredoc 안에서 `\n`, `\t` 같은 이스케이프가 바뀌어 버립니다. TS 파일 수정은 Edit 도구로 하는 것이 안전합니다.

**관리자 데이터**
- 문제 사례 키 형식은 `<16자리 hex 설치ID>:<8~64자 id>`입니다(`review.ts` `decideCase`). 시험 데이터의 turn id도 8자 이상이어야 합니다.
- 관리자 데이터 폴더(`admin-data`)는 사용자 데이터 폴더(`data`)와 따로 있습니다.
