# AI 미설치 PC와 로그인 창 수정 (0.1.13)

## 확인

- 사용자 PC에는 `%APPDATA%/npm/gemini.cmd`와 그 대상인 Gemini 패키지가 존재했다. 설치 탐색 결과가 `missing`이 아닌 이유다.
- 기존 창 실행은 `detached: true`, `stdio: ignore`로 PowerShell을 시작한 직후 성공을 반환했다.
- 같은 방식으로 확인 스크립트를 실행하면 종료 코드 0인데도 스크립트의 시작 확인 파일이 생성되지 않는 현상을 재현했다. 현재 설치본의 Node 22에서도 같았다.
- 기존 테스트는 설치 스크립트를 현재 콘솔에서 실행했으므로 실제 새 창 실행 실패를 검출하지 못했다.

## 수정

- `setupProcess.ts`: 숨긴 실행 도우미에서 `Start-Process -WindowStyle Normal`로 별도 입력 가능한 콘솔을 연다.
- 새 콘솔에서 입력·출력이 리디렉션되지 않은 것을 확인한 후에만 팔레트에 창을 열었다고 알린다.
- 실행 실패·준비 실패·15초 시간 초과를 오류로 반환하고 직접 시작한 실패 프로세스 트리를 정리한다.
- AI별 중복 실행은 준비 중부터 막고 창 종료 시 설치 탐색 캐시를 비운다.
- 경로·AI 이름은 환경변수로 넘긴다. 코드 문자열에 사용자 경로를 삽입하지 않는다.
- 로그인은 별도의 임시 작업 폴더에서 실행하며 창을 닫은 뒤 임시 상태 파일을 정리한다.
- PowerShell은 Windows 시스템 폴더의 절대 경로로 실행해 PATH에 PowerShell이 없어도 동작한다.
- 팔레트는 상태 확인 오류 시 설치·로그인 질문으로 넘어가지 않는다. 창 실행 실패 시 버튼을 다시 활성화한다.
- 설치·로그인 스크립트의 치명적 오류도 창에서 확인할 수 있게 유지한다.
- Gemini는 실행 후 Google 로그인 방식을 선택해야 브라우저로 이어진다. 안내 문구를 이 순서에 맞췄다.

## 검증

- 플러그인 Release 빌드 경고·오류 0, 서버 TypeScript 빌드·lint 통과.
- 실제 별도 콘솔에서 Claude·Codex·Gemini 미설치 확인 실행과 입력·출력 준비 확인 통과.
- 한글·공백·작은따옴표 경로, 잘못된 스크립트 경로, 콘솔 준비 거부 검증 통과.
- 격리된 가짜 CLI/npm으로 Codex·Gemini 설치·로그인·재로그인, Gemini 미설치 상태의 로그인 거부와 설치 실패 후 missing 유지 통과.
- 배포된 Node/npm과 같은 사용자 전용 CLI 경로를 검증했다. 관리자 권한이나 별도 시스템 Node 설치가 필요하지 않은 흐름이다.
- 실제 Google 브라우저 계정 인증은 사용자에게 맡긴다. 테스트에서는 실제 AI 설치나 로그인 변경을 하지 않았다.

공식 Gemini 흐름 참고: [설치](https://geminicli.com/docs/get-started/installation/), [인증](https://geminicli.com/docs/get-started/authentication/).
Claude 공식 Windows 설치 방법도 [공식 설치 문서](https://code.claude.com/docs/en/setup)와 대조했다.

## 다른 PC에서 확인할 순서

1. 서명된 0.1.13 EXE를 실행해 설치하고 Civil 3D 팔레트를 연다.
2. CLI가 없는 AI를 선택한다. 로그인 질문이 아닌 설치 질문이 나와야 한다.
3. 설치를 누르면 입력 가능한 PowerShell 창에서 다운로드와 설치가 진행되고 로그인으로 이어져야 한다.
4. Gemini는 Google 로그인 방식을 선택하고 브라우저 인증을 마친 뒤 `/quit`을 입력한다. 마지막 안내에서 엔터로 창을 닫는다.
5. 팔레트의 새로고침(↻)을 누르면 로그인 상태를 확인하고 해당 AI를 선택해 사용할 수 있어야 한다.

CLI가 이미 설치돼 있고 인증만 안 된 경우에는 로그인 버튼으로 별도 PowerShell 창을 열어 인증만 진행한다.
완료 후 새로고침 절차는 동일하다. 사용량 조회만 하던 새로고침에 실제 인증 재확인을 연결했고,
선택된 AI가 없어도 마지막으로 설치·로그인 창을 연 AI를 확인한다. 미완료·조회 오류 시 사용할 수 있다고 표시하지 않는다.
실제 ChatPanel을 링크한 WPF 테스트에서 설치/로그인 분기, 선택 전 새로고침, 미완료 인증,
네트워크 실패·재시도, 창 실행 실패·재시도와 작업 중 중복 새로고침 방지를 검증했다.

네트워크 차단이나 설치 실패 시 오류를 창에서 확인할 수 있어야 하며, 실제로 설치되지 않은 AI를 ready로 표시하면 안 된다.

## 배포 상태

0.1.12 설치 후 PATH 제한 조건 검증에서 추가 문제를 발견해 시스템 PowerShell 절대 경로 실행을 보완했다.
설치·인증 후 새로고침으로 연결 확인하는 사용자 요청까지 0.1.13에 반영했다.
전체 기능·WPF UI 검사, 설치·업데이트·복구·데이터 보존, EXE 설치·재설치·제거·변조 거부 검증을 통과했다.
0.1.13 로컬 설치를 완료했고, 기존 사용자 파일 66개의 해시가 설치 전후 동일했다.
설치본의 동봉 Node로 PowerShell 경로가 PATH에 없는 조건에서 세 AI용 콘솔 실행·입출력 준비를 모두 확인했다.
백업: `.package-cache/installed-backups/0.1.12-44ca04f575a345c585c619ceadf2db7f`.
설치 결과: `.package-cache/install-0.1.13-result.json`.
공개 업로드·커밋·태그·푸시는 하지 않는다.

## 가상환경 테스트 범위

사용자가 가상환경 테스트를 이번 작업에서 제외했다. Windows Sandbox·VM 기능 활성화와 재부팅은 진행하지 않았다.
위 검증은 실제 별도 콘솔 실행과 격리된 가짜 CLI 시나리오이며, 깨끗한 가상 PC에서 실제 세 AI를 설치·인증한 결과가 아니다.
