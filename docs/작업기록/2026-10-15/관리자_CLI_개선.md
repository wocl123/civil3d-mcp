# 관리자 CLI 사용성·대기 문제 개선

사용자가 관리자 BAT에서 메뉴 이동 시 오래 기다리거나 이전 출력이 계속 쌓여 읽기 어렵다고 보고했다.
로그인·새로고침 0.1.13 로컬 설치를 완료한 뒤 이 작업을 진행했다.

## 확인한 대기 구조

- 시작 동기화를 전부 기다린 뒤에야 첫 메뉴를 표시했다.
- 자동 동기화와 메뉴 작업이 같은 Promise 대기열에 들어갔다. 앞 작업이 끝나지 않으면 뒤 메뉴도 기다렸다.
- 지식 승인 후 원격 동기화까지 기다렸고, 사용자 목록 조회도 원격 폴더를 탐색했다.
- 작업 시간 제한이나 취소 입력이 없었다. 메뉴는 화면 전환 없이 console.log를 계속 추가했다.

실제 사용자 PC에서 발생한 모든 멈춤의 원인을 특정한 것은 아니다. 위 대기 경로를 제거·제한하고,
일부러 작업 프로세스의 이벤트 루프를 멈추는 재현 테스트로 복구 동작을 검증했다.

## 변경

- 화면별 제목·이동 위치, 메인 메뉴·상세·결과 화면을 분리했다. TTY에서는 전환할 때 화면을 지운다.
- 화면 폭에 맞춰 한글을 줄 바꿈하고 긴 내용은 페이지로 나눈다. n/p로 이동한다.
- 0/Enter/Esc로 이전 메뉴, q로 종료한다. 메인 메뉴의 0은 종료다.
- 버전·메모 같은 입력 도중 Esc/입력 종료는 저장하지 않고 취소한다. 일반 한글 입력은 계속 보인다.
- 실제 저장·조회·수집은 별도의 관리자 작업 프로세스에서 실행한다. 화면과 입력은 기다리는 동안에도 응답한다.
- 작업 시간과 제한을 표시한다. 기본 제한은 일반 작업 20초, 가져오기 120초이며 Esc로 중단할 수 있다.
- 시간 초과·중단 시 직접 시작한 작업 프로세스가 종료된 것을 확인하고 다음 작업을 받는다.
  작업을 자동 재전송하지 않으며, 저장·가져오기 결과가 일부 반영됐을 가능성은 목록에서 확인하도록 안내한다.
- 작업 프로세스가 정상 실행되는 동안에는 목록 번호→실제 ID의 연결을 유지한다.
  작업 프로세스가 중단되면 화면은 메인으로 돌아가 새 목록을 확인하게 한다.
- 관리자 창이 사라지면 작업 프로세스도 IPC 연결 종료를 감지해 종료한다.
- 첫 메뉴 표시를 동기화가 막지 않는다. 자동 가져오기는 10분 간격이며 메인 메뉴에서 30초 이상 입력이 없을 때 실행한다.
  안쪽 메뉴·입력 중에는 미루고, 중복 작업을 대기열에 쌓지 않는다. 1번은 즉시 가져오기다.
- 관리자 메뉴의 사용자 목록은 로컬 보관함을 보여준다. 새 사용자 수집은 가져오기에서 한다.
- 지식 승인은 저장 결과를 먼저 보여준다. 사용자에게 전달하는 동기화는 1번 또는 자동 가져오기에서 한다.
  기존 메뉴 밖 명령 호출의 동기화 방식은 기본값으로 유지한다.
- BAT는 시스템 PowerShell 절대 경로를 사용하며 정상 종료 시 추가 pause를 요구하지 않는다.
- 관리자 실행 시 변경된 TypeScript나 빠진 산출물이 있을 때만 빌드한다.
  시스템 Node가 없으면 설치된 Civil 3D 번들의 Node를 사용하며 npm 없이도 기존 빌드 도구를 실행할 수 있다.

## 주요 파일

- `server/src/admin/console.ts`: 입력·화면과 작업 연결, 유휴 자동 수집.
- `terminal.ts`: 화면 전환, 페이지, 한글 폭, 입력 보존, Esc·Ctrl+C.
- `adminWorker.ts`, `worker.ts`, `jobs.ts`: 작업 실행·기한·종료 확인과 기존 검토 명령 재사용.
- `menu.ts`: 번호 메뉴, 결과 확인, 뒤로 이동, 입력 취소.
- `server/src/workflows/centralCommands.ts`: 관리자 메뉴의 로컬 조회·동기화 지연 옵션. 기본 호출은 기존 동작.
- `scripts/admin.ps1`, `관리자실행.bat`: 시작·빌드·런타임·종료 개선.

## 검증

- TypeScript 빌드, lint, 관리자 회귀 검사 통과.
- 사례 분류→수정 요청서→완료, 지식 승인, Drive가 없는 상태의 로컬 사용자 조회·승인 확인.
- 입력 도중 EOF 시 사례 완료 상태를 바꾸지 않는 것 확인.
- 실제 readline 경로에서 한글 입력, 화면 초기화, 좁은 창 페이지 이동, 첫 페이지 경계, Esc 뒤로 이동 확인.
- 작업 표시를 다시 그리는 동안 입력 중인 한글이 유지되는 것 확인.
- 연속 요청 시 상태 유지, 오류·프로세스 종료 후 복구, 이벤트 루프가 멈춘 경우 시간 초과 확인.
- 중단된 작업이 나중에 파일을 쓰지 않는 것과 관리자 종료 후 작업 프로세스가 남지 않는 것 확인.
- 실제 BAT를 임시 데이터 폴더로 두 번 실행해 정상 종료·빌드 재사용 확인.
  시스템 Node/npm이 PATH에 없는 조건에서도 설치된 번들의 Node로 실행됐다.
- 기존 Drive 수집·승인·사용자 관리 및 웹 수신 end-to-end 검사 통과.

## 적용

관리자 BAT는 저장소의 `server/build/admin/console.js`를 실행하므로 이번 개선은 관리자 창을 다시 열면 적용된다.
관리자 개선을 적용하기 위해 사용자용 EXE를 다시 설치할 필요는 없다.
팔레트 로그인·새로고침 수정본은 별도로 0.1.13 로컬 설치와 설치본 콘솔 실행 검증을 마쳤다.
가상환경 기능 변경·재부팅·공개 업로드·커밋·푸시는 하지 않았다.
