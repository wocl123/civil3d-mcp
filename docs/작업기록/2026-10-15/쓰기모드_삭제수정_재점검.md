# 삭제·수정 쓰기 모드 재점검 (0.1.15)

## 사용자 보고

지표면 삭제 시 ForWrite 관련 오류가 발생했다. 삭제·수정 경로 전체와 객체뷰어·객체 분리 반영 여부를 점검했다.

## 확인 및 수정

- 지표면·종단·선형·레이어 편집에서 일반 `Transaction.GetObject(..., ForRead)`로 읽은 객체를
  `UpgradeOpen()`으로 쓰기 전환하고 있었다.
- 일반 트랜잭션은 동일 트랜잭션의 `GetObject(..., OpenMode.ForWrite)`로 다시 열도록 통일했다.
  지표면 삭제/편집, 종단 편집, 선형 속성 편집, 레이어 테이블 생성 및 레이어 편집/삭제가 대상이다.
- 기존 선형·종단 삭제와 설계 값 변경, 레이어 소속 객체 삭제는 이미 ForWrite로 열고 있어 유지했다.
- 조회와 계획 단계는 ForRead를 유지하며 참조·리비전·동의·Undo 검증도 유지했다.
- 일반 CAD 예외에는 메서드명·CAD 오류 상태·스택을 로컬 `service.log`에 남기도록 보강했다.
  요청 인자와 인증 토큰은 기록하지 않고, 스택은 AI 응답에 포함하지 않는다.

[Autodesk 객체 열기 모드 지침](https://help.autodesk.com/cloudhelp/2026/DEU/OARX-DevGuide-Managed/files/GUID-CC5CC229-B122-4897-A8DA-5C5ADADB0F38.htm)은
일반 Transaction으로 읽은 객체는 GetObject로 원하는 모드로 다시 열도록 안내한다.

## 검증 범위와 한계

- 사용자의 원본 오류와 동일한 실패 조건은 확보하지 못했다. 기존 코드도 단순 시험 도면에서는 통과했다.
  따라서 일반 트랜잭션에 부적합한 쓰기 전환 패턴을 제거한 것이며, 원본 오류를 재현해 원인을 확정했다고 보고하지 않는다.
- 기존 시험은 새 프로세스의 빈 도면 안에서 생성하고 편집하는 방식이었다.
  별도 프로세스에서 시험 DWG를 저장하고, 또 다른 프로세스에서 다시 열어 편집·삭제하는 시험을 추가했다.
- 저장 도면 시나리오: 일반 TIN·붙여넣기 지표면·토공량 지표면 삭제,
  참조 중인 지표면 삭제 차단, 지표면 표고/설명 수정,
  종단 형상/이름 수정, 선형 속성 수정, 레이어 잠금/동결 수정,
  종단 삭제 및 레이어/소속 객체 삭제.
- 지표면에 EG 종단이 연결된 상태로 저장·재열기한 추가 시험에서도 지표면 편집과 나머지 시나리오가 통과했다.
- 사용자 도면을 수정하지 않고 임시 프로필과 시험 DWG만 사용한다.
- 2025 로컬 엔진으로 패키징할 때 기존 22항목과 저장·재열기 시나리오 10개를 자동 실행하도록 추가했다.

## 객체뷰어·객체 분리

- 0.1.15 설치본의 동봉 Node/MCP 서버에서 `plan_drawing_display` 등록과 표시 동작 스키마를 확인했다.
- `isolate` / `hide` / `restore`는 AutoCAD 기본 객체 분리·숨기기·분리 해제를 호출한다.
  같은 레이어 객체의 개별 분리·복원을 실제 Civil 엔진에서 다시 검증했다.
- `viewer`는 선택 핸들을 지정한 뒤 `_AecObjectViewer` 열기 요청을 예약한다.
  Civil 3D 2025 설치 메뉴의 실제 명령과 일치한다. 창이 열렸다고 미리 성공 판정하지 않는다.
- 객체뷰어 창의 실제 UI 렌더링은 Core Console 자동 시험의 검증 범위에 포함하지 않는다.
