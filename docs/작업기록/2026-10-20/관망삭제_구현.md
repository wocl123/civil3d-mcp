# 관망 조회·일괄 삭제 구현 (2026-10-20)

원본: 관리자 보관함 `수정요청-2026-10-20.md` 사례 1.
요청: `Raker-KickerBlock`으로 되어 있는 네트워크 전체 삭제.

## 변경

- `list_pipe_networks`: 전체 중력식 관망을 검색한 뒤 페이지 처리. 이름·핸들·레이어·관/구조물 개수·참조 여부를 제공한다. 요약에서 생략된 관망도 검색한다.
- `plan_pipe_network_delete`: 정확한 이름/핸들 하나, 명시한 목록 또는 이름 포함 조건 중 하나로 삭제 계획을 만든다. 이름 포함 조건은 번호가 붙은 관망도 포함한다.
- 계획에는 각 관망 이름·핸들·관/구조물 개수와 연결 라벨을 포함한 전체 삭제 수를 표시한다. 다른 레이어의 소속 객체도 삭제하며 레이어는 남긴다.
- 기존 진행/취소, 도면·리비전 확인, 작업 기록과 Undo 흐름을 사용한다. 계획의 핸들을 고정하며 적용 직전 이름·소속 구성·종류·레이어와 참조/잠금 상태를 다시 검사한다.
- 참조 객체, 잠긴 레이어, 지원하지 않는 Civil 연관 객체가 발견되면 전체 계획을 거절한다. 삭제 중 오류는 하나의 트랜잭션으로 전체 취소한다.
- 압력식 관망은 이번 기능의 지원 범위에 포함하지 않는다.

## 검증 구성

- MCP 시나리오: 60개 중 요약 밖 대상 검색, 페이지, 잘못된 선택 조건, 계획의 읽기 전용 동작, 승인 전 적용 거절, 승인 후 일괄 삭제, 다른 관망 보존, Undo.
- 실제 엔진: Autodesk `Pipe Networks-3C.dwg`를 임시 폴더에 복사하여 검사한다. 원본 예제와 사용자 도면은 변경하지 않는다.
- 실제 엔진에서 번호/빈 관망, 전체 검색, 잠긴 소속 객체에 대한 전체 거절, 계획 후 이름 변경 거절, 트랜잭션 취소, 관·구조물 및 발견된 라벨 삭제, 다른 관망 보존, Undo, 단일 핸들/명시 목록 삭제를 검사한다.
- 위 엔진 검사를 `내부테스트.bat`의 `native-civil.mjs --networks` 단계에 포함했다.

## 수동 확인

내부배포 후 Civil 3D를 평소처럼 실행하여 `Raker-KickerBlock 네트워크 다 삭제`를 요청한다.
계획의 대상 목록·개수를 확인하고 진행한 뒤 해당 관망과 소속 객체의 삭제, 다른 관망 보존, 되돌리기를 확인한다.
실제 팔레트 수동 확인 전에는 전체 완료 또는 관리자 사례 완료로 처리하지 않는다.
정식 버전은 0.1.16을 유지하며 공개 Release는 게시하지 않는다.
