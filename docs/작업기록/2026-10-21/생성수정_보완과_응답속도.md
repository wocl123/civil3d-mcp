# 생성·수정 보완과 질문 처리 시간 단축

## 구현한 보완

| 기능 | 코드 및 MCP 경로 | 동작 |
| --- | --- | --- |
| COGO 측량점 | CogoChanges / list_cogo_points, plan_cogo_point_create/edit | 명시 점번호와 XYZ 생성, 번호 충돌 차단, 좌표·표고·설명·스타일 수정 |
| 실제 중력식 관·구조물 | NetworkCatalog, NetworkPartAccess/Changes, NetworkPipeChanges / list_pipe_parts, list_pipe_network_parts, plan_pipe_create/edit, plan_structure_create/edit | 정확한 규격 선택, 실제 생성, 관 중심선·관경·연결/해제, 구조물 위치·회전·상단/바닥 표고 |
| TIN 토공량 | VolumeChanges / get_volume_surface, plan_volume_surface_create/edit | 기준·비교 TIN 생성, 절성토 계수·속성 수정, 보정 전/후 체적 조회 |
| 스타일·좌표 단위 | CivilStyles, CivilCoordinates / list_civil_styles | 기존 스타일 조회, 계획에 WCS·Civil 단위·삽입 단위·좌표계 표시 |

모든 변경은 기존 계획 표시 → 사용자 동의 → apply_drawing_change → 검증/트랜잭션/Undo 흐름을 따른다.
COGO는 AutoCAD POINT와 구별하고, 측량 DB/프로젝트/잠금 점을 임의로 수정하지 않는다.
관경 수치를 카탈로그 단위로 추측하거나 근사 규격으로 대체하지 않는다. 실제 부품군·규격 이름/핸들을 사용한다.
관 좌표 Z는 중심선이며 관저 표고와 다르다. 규격 교체는 중심선을 유지하므로 관저·관정·토피가 달라질 수 있다.
연결 교체는 replaceConnections를 명시해야 하고, 구조물과 관 끝의 XY가 일치해야 한다.
설계 규칙을 자동으로 적용하지 않으며, 검사하는 같은 관망의 부품/라벨 중 잠금·참조 객체가 있으면 차단한다.
토공량의 실제 공통 삼각망은 적용 시 검사하며 없으면 전체 생성을 롤백한다. 원본 지표면은 변경하지 않는다.

## 실제 지연 분석

이 PC 내부 데이터의 2026-10-20 요청 6건에서 질문 원문 없이 시간·도구 횟수만 집계했다.

- 총 응답 시간: 6.94~16.21초, 평균 약 10.08초.
- AI 전 도면 문맥 준비: 47~141ms. AI 실행 준비: 5~185ms.
- 첫 도구가 있는 5건: 질문부터 첫 도구 호출까지 2.81~7.33초.
- 기록된 Civil 도구 11회: 각 49~170ms, 합계 800ms.
- 가장 긴 16.21초 요청은 도구 5회를 사용했다.

이 표본에서는 모델이 판단·답변하는 시간이 주된 지연이다. 표본이 6건이므로 모든 도면/AI에 일반화하지 않는다.
이미 적용된 HTTP MCP 재사용과 한 번의 도면 문맥 조회를 유지하며, 사용자 모델을 임의 변경하지 않았다.

## 이번 단축 경로

`quickDrawing.ts`에서 정확히 일치하는 요청만 코드로 분류한다.

- `치수선 다 삭제`, `일반점 다 삭제`, `일반문자 다 삭제` 및 명확한 동일 표현: 기존 계획 도구로 직접 연결.
- `치수선 목록`, `지표면 목록`, `관망 목록`, `COGO 점 목록`: 신선한 도면 조회로 표를 직접 작성.
- 단일 계획을 보여 준 직후 `진행`, `적용해줘`, `고고`, `ㄱㄱ` 등 명확한 동의: 기존 guarded apply 사용.
- 제외 조건·선택 대상 제한·복합 작업·부정문·가능 여부 질문·모호한 점 삭제는 직접 처리하지 않고 기존 AI 경로 유지.

직접 계획은 삭제하지 않는다. 도면 ID/리비전, 변경된 기준, 취소, 기존 사용 여부 등 검증을 그대로 통과해야 한다.
직접 조회도 도면 리비전 전후를 검사하며 오래된 답변을 반환하지 않는다. 표시 한도는 50개이며 이어보기는 AI 경로다.
직접 경로는 AI 설치/로그인 없이도 동작하고 모델 토큰을 사용하지 않는다. 도구·턴 로그에 fastPath를 기록한다.
모델 경로에는 기존 firstToolMs에 더해 firstTextMs와 aiFinishedMs를 남겨 첫 답변과 이후 처리 시간을 분리했다.

가상 브리지를 사용한 회귀 검사에서 직접 계획은 28ms로 측정됐다. 이는 실제 Civil 3D/AI의 전후 비교 수치가 아니다.
`server/scripts/fast-path-live-read.mjs`로 실제 열려 있는 Civil 3D에 연결해 치수선 목록 조회만 3회 계측했다.
서버의 질문 처리부터 목록 반환까지 295/150/154ms(평균 200ms), 모델 호출 0회, 별도 Node 모듈 초기 로드 54ms였다.
이 검사는 작업 도면에 쓰지 않고 AI·계획·설치도 실행하지 않으며, 결과 로그는 격리한 `.package-cache/live-fast-read-*`에 저장한다.
개발 서버 코드와 기존 설치 플러그인의 읽기 경로를 연결한 측정이므로, 실제 팔레트 UI의 전후 비교나 복잡한 설계 질문의 가속 수치로 해석하지 않는다.
최종 전체 내부 테스트와 내부배포는 사용자가 Civil 3D 작업 중이라고 알려줘 종료 시점까지 대기한다. 새 팔레트의 수동 확인도 별도다.

## 검증 및 남은 범위

- EngineeringTests: COGO·토공량 생성/편집, 충돌·잠금·오래된 계획 거부, 알려진 평면의 실제 체적, 롤백·Undo.
- NetworkPartTests: 실제 Autodesk 예제의 카탈로그로 생성·연결·규격 교체·표고 수정·명시 연결 교체/해제·Undo.
- 새 프로세스에서 DWG를 다시 열어 COGO·토공량·관·구조물의 결과 유지 및 추가 수정 확인.
- Primitive MCP: 신규 조회와 계획/동의/적용, 직접 경로에서 다음 턴 동의 전 쓰기 금지, 부정/복합 요청 분류 거부.
- 전체 내부 자동 검증은 scripts/internal-test.ps1 결과를 기준으로 보고한다. 실제 팔레트 수동 확인은 별도로 남긴다.

형상선·횡단·코리더 생성/수정, 압력관망 등은 이 보완에 포함하지 않는다.
향후 복합 설계의 왕복을 줄이려면 여러 부품을 한 계획으로 검증하는 배치 도구와 모델별 구간 측정이 필요하다.
모델/추론 수준 변경, 도구 설명 축소, 모델 프로세스 상시 재사용은 품질·권한·취소 검증을 동반해 별도로 판단한다.
