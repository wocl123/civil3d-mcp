# 관리자 완료·버림 사례의 Drive 원본 정리

## 동작

관리자 BAT의 5번에서 완료 처리하거나 문제 사례에서 버리면, 기존 관리자 보관함 내용 삭제에 더해 Drive 수집 폴더의 해당 원본 기록도 정리한다.

- 대상은 해당 설치 ID + 질문 ID의 turn/tool/change/feedback 기록이다.
- 같은 묶음의 다른 질문·미해결 사례는 원문 필드와 함께 보존한다.
- 일부 기록이 남으면 그 파일만 원자적으로 갱신하고, records가 비면 해당 JSON 파일을 삭제한다.
- 날짜별 폴더와 예전 평면 packages 폴더를 모두 처리한다. 지식 후보·승인 지식·설치 파일은 이 기능의 삭제 대상이 아니다.
- 관리자 통계와 처리 이력(분류·고친 버전·메모)은 남는다.
- 삭제 대기를 cases.json에 먼저 남긴다. Drive 연결 실패·워커 종료 시 다음 동기화에서 다시 처리하며, 메인 화면에 대기 건수를 표시한다.
- 메뉴 **8. 완료·버린 사례 Drive 삭제 재시도**로 과거에 완료/버림 처리한 항목도 다시 정리할 수 있다.
- 삭제를 마친 사례도 이후 수집 때 다시 확인한다. 늦게 재전송된 원본은 다시 정리하고, 로컬 addPackage 단계에서도 삭제한 내용을 재유입시키지 않는다.
- 승인된 사용자 폴더·이미 가져온 패키지만 변경한다. 차단 사용자, 위조/복사 폴더, 외부로 향하는 링크, 잘못된 패키지, 검사 중 바뀐 파일은 삭제하지 않고 대기로 남긴다.
- Drive 삭제 작업에는 기존 동기화용 제한 시간을 적용하고 Esc로 중단할 수 있다. Drive에 중단 후 남을 잠금 디렉터리는 만들지 않는다.

## 용량 반영

이 기능은 관리자 PC의 Drive for Desktop 수집 폴더에 삭제/축소를 요청한다. 표시하는 바이트 감소는 원본 JSON 파일 크기 기준이며 C드라이브 여유 공간이나 Google 계정의 즉시 반환량을 뜻하지 않는다.
클라우드 반영은 Drive 동기화 상태에 달려 있다. [Google 안내](https://support.google.com/drive/answer/2375102?hl=ko)에 따르면 휴지통 파일도 영구 삭제 전까지 저장용량에 포함된다. 삭제한 해당 파일의 영구 삭제는 Drive 휴지통에서 별도로 해야 한다. 다른 사용자 파일까지 영향을 주는 전체 휴지통 비우기는 자동화하지 않았다.

## 검증 및 적용

- `npm run test:admin`: 번호 메뉴, 실제 명령/보관함/임시 Drive를 연결한 삭제 시험, 워커·터미널·BAT 검증 통과.
- 새 `server/scripts/admin-cleanup.mjs`: 혼합/빈 파일, 연결된 도구·변경·의견, 다른 설치의 같은 질문 ID 보호, 원문 메타데이터 보존, 오프라인 및 재시작 후 재시도, 늦은 재전송, 미수집·차단·잘못된 JSON·junction 경계 보호, 관리자 외부 요청 거부 검증.
- `node scripts/drive-e2e.mjs`: 기존 수집·검토·지식 승인·사례 분류·배포·보관 기한 회귀 통과.
- `node scripts/primitive-scenario.mjs`: 취소 분류와 관리자 사례 회귀 통과.
- `node scripts/ingest-e2e.mjs`: 실제 수신 코드 기반 등록·전송·재시도·중복 방지·사용자 격리·관리자 가져오기 회귀 통과.
- `npm run lint`: 통과.

실제 사용자 Drive 원본은 시험 대상으로 지우지 않았다. 실제 클라우드 삭제 완료를 자동으로 확인했다고 주장하지 않는다.
현재 작업 공간의 관리자 BAT는 서버 빌드를 사용하므로 창을 닫고 다시 열면 적용된다. 공개 배포/설치본 0.1.16을 덮어쓰거나 새 버전을 배포하지 않았다.
