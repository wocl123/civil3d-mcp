# 팔레트 응답 속도 개선 (0.1.16 배포)

추가 수정 후 사용자 배포 요청에 따라 0.1.16으로 공개 배포하고 현재 PC에도 설치했다.
아래 설치 보류 이력은 최초 작업 당시 기록이다. 최종 결과는 [배포 기록](0.1.16_배포.md)을 참고한다.

## 변경

- 팔레트의 MCP 도구 서버를 로컬 서비스 안의 HTTP 서버로 재사용한다.
  요청마다 별도 Node 프로세스를 시작하고 모든 도구 모듈을 다시 읽던 비용을 제거했다.
  CLI의 MCP 초기화와 세션은 질문별로 구분되며 AI CLI 자체는 질문마다 실행한다.
- 질문마다 별도 임시 접근 토큰과 고정된 요청 ID·도면 ID·허용 수정안 목록을 사용한다.
  완료·실패·취소 시 토큰을 폐기하고, 누락된 정리에도 4분 뒤 만료한다.
  서비스의 전역 환경 변수는 변경하지 않는다.
  세션 종료 시 진행 중 CAD 연결도 닫고, 종료된 요청의 비동기 콜백이 추가 CAD 명령을 보내지 못하게 한다.
  이미 전송된 변경의 결과는 기존 작업 영수증으로 확인하며 응답 유실만으로 미적용을 단정하지 않는다.
- 도면 ID·리비전·선택·선형/종단 개요를 같은 도면 잠금 안에서 한 번에 읽는
  `drawing.chat_context`를 추가했다. 개요 준비 중 전체 Model Space 객체 수를 세거나
  선형마다 전체 형상 스냅숏을 만드는 조회를 없앴다. 구형 플러그인은 기존 개별 조회로 돌아간다.
  선택 또는 선형 개요 조회 실패는 로컬 로그에 남기고 해당 선택/개요만 생략한다.
- CLI 실행 PATH의 레지스트리 조회 결과를 1분간 재사용한다. 설치·인증 창 종료 시와
  명시적인 최신 PATH 요청 시에는 새로 읽는다.
- 바로 앞 답의 수정안이 하나이고 사용자가 정확히 `진행`, `적용해줘` 등으로 동의하면
  AI 호출 없이 적용 버튼과 같은 검증·커밋·재검토 경로로 실행한다.
  여러 수정안, 부정문, 이미 적용/취소한 계획, 일반 질문은 이 단축 경로로 실행하지 않는다.
- 프롬프트의 최신 객체·선택 정보를 다시 목록 조회하지 않도록 AI 지침을 보강했다.
- 로컬 `turns.jsonl`에 `timing.contextMs`, `beforeAiMs`, `prepareMs`,
  `firstCliEventMs`, `firstToolMs`, `cliMs`를 해당되는 경우 남긴다.

## 검증

- 실제 SDK의 HTTP MCP 연결, 동시 요청별 수정안·로그 귀속, 허용되지 않은 수정안 적용 거절,
  도면 변경·리비전 변경 차단, 토큰 없는 요청·외부 Origin·폐기한 토큰 차단을 검사했다.
- Claude/Codex/Gemini 각각의 HTTP 연결 설정을 검사했다. 기존 stdio 진입점도 유지한다.
- AI가 없는 시험 환경에서 단일 계획에 대한 `진행`이 사용량 0으로 적용되는 것을 확인했다.
  부정문·복수 계획·중복 적용·계획 뒤 도면 변경도 검사했다.
- MCP 준비(초기화 + 도구 목록) 4회 비교:
  - 기존 별도 프로세스: 236 / 251 / 238 / 241 ms.
  - 재사용 서비스: 9 / 13 / 8 / 9 ms.
  - 패키징 중 재검사: 기존 237 / 243 / 242 / 235 ms, 개선 8 / 8 / 10 / 10 ms.
- 위 수치는 로컬 MCP 준비 시간이며, 전체 AI 답변 시간이 20배 이상 빨라졌다는 뜻은 아니다.
  모델 판단·네트워크·일반 질문의 CLI 시작 시간은 남는다. 모델과 추론 강도는 변경하지 않았다.
- 설치된 실제 Claude와 Codex에서 시험 브리지의 `list_surfaces`를 한 번 호출하는 테스트를 통과했다.
  Claude는 준비 203ms / CLI 실행 4,966ms, Codex는 준비 7ms / CLI 실행 12,664ms였다.
  서버 첫 로드 비용은 첫 요청에 포함되고 이후 재사용된다. 서로 다른 모델의 단일 요청 결과이므로
  공급자 성능 비교나 변경 전후 전체 응답 속도 개선율로 사용하지 않는다.
  Gemini는 설정·프로토콜 검증까지만 수행했으며 실제 Google 계정 요청은 수행하지 않았다.
- TypeScript/C# 빌드와 lint, 전체 Civil·설계·안전성·삭제·수정·레이어 회귀 시험을 통과했다.
- Civil 3D 2025의 임시 시험 도면에서 새 일괄 조회와 기존 CRUD/Undo/객체 분리를 확인했다.
  결과: `.package-cache/native-crud-1792124960902/result.json`.

## 설치

- 사용자 요청으로 추가 수정사항을 반영한 뒤 한 번에 버전업하기로 했다.
- 진행 중인 패키징을 중지했고, 소스의 버전 표기는 기존 0.1.15로 되돌렸다.
- 현재 PC의 0.1.15 설치본은 교체하지 않았다. 속도 개선 코드는 작업 트리에 유지한다.
- 동봉 런타임에서 stdio/HTTP MCP, 권한 폐기, 최종 빌드와 패키지 코드 일치를 확인했다.
  임시 설치·업데이트·복구·변조 거부·제거·사용자 데이터 보존 검사도 통과했다.
  최종 EXE 설치 검증과 현재 PC 적용은 보류했다.
- C드라이브 여유 공간 부족으로 패키징 임시 경로를 프로젝트의 D드라이브 경로로 변경했다.
  사용자 파일은 삭제하지 않았고, 재부팅하지 않았다.
