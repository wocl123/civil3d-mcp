# 기능별 코드 디렉터리

기능 구현과 관련 모델은 같은 큰 카테고리에서 관리한다. C#은 기존 PascalCase 디렉터리 관례를, TypeScript는 기존 소문자·camelCase 관례를 따른다. 폴더 이동으로 CLR 네임스페이스, MCP 도구 이름, 입력값 또는 동작은 바꾸지 않는다.

## 모델과 데이터 읽기

- 선형 C# 모델은 `plugin/Civil/Alignment/Models/`, 종단 모델은 `plugin/Civil/Profile/Models/`에 둔다. 공통 변경 결과·요청 모델은 `plugin/Civil/Workflow/Models/`에 둔다.
- 서버 선형 기록과 타입은 `server/src/civil/alignment/`, 종단 타입은 `server/src/civil/profile/`에 둔다.
- 도면 요약·선택·채팅 컨텍스트·공통 페이지 읽기는 `server/src/civil/shared/`에서 관리한다.
- 설계기준 계산은 기존 `server/src/criteria/`, 선형 배치 계산은 `server/src/design/`, MCP 연결은 `server/src/bridge/`의 역할을 유지한다.

## 도구 등록과 공통 실행

`server/src/mcp/tools/registration/`은 기능별 도구를 등록 순서대로 연결하는 파일이다. 새로운 도구의 입력 스키마와 실행 콜백은 해당 기능 폴더에 작성하고 등록 파일에서는 등록 함수만 호출한다.

`server/src/mcp/tools/shared/planCivil.ts`가 Civil 미리 보기와 변경안 저장을 담당한다. 공통 입력 규격은 shared의 스키마 모듈을 사용한다. 기존 등록 그룹의 서로 다른 기본값과 안내 문구는 보존한다.

`plugin/Civil/Workflow/CivilOperationHandlers.cs`에는 DB 작업의 검증·적용 함수를 함께 등록한다. `CivilPlans.cs`가 지문 비교와 트랜잭션을 관리한다. 기본 대화형 명령과 연속 작업은 기존 문서 컨텍스트 처리 경로를 사용한다.

새 기능은 해당 카테고리에 추가한다. 실제로 여러 카테고리에서 사용하는 코드만 Shared에 둔다. 테스트용 명시적 Compile 경로와 TypeScript import는 이동할 때 함께 갱신한다.
